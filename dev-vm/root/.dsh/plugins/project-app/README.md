# DevVM Project-app bridge

This native Web-profile file package connects a selected Project's DSH UI to the Control-origin app. The daemon provides `DEVVM_EMBED_PROJECT_ID` and `DEVVM_CONTROL_ORIGINS` at launch. The host validates exact origins and injects them through `webserver/index-inject`; the child activates inside the parent frame with that metadata. Ordinary top-level DSH keeps its native behavior.

The package uses native `sessions`, `connection`, `conversation`, `uiWorkspace`, `layout`, and `slots` services plus authenticated `remote.session`, the native module loader/React runtime, and native UI primitives. It registers its sidebar button in `conversation.header.leading`. At child widths up to 1023px, a qualifying one-finger right swipe anywhere opens native navigation and a left swipe anywhere closes it. Capture listeners cover the drawer and backdrop; vertical intent/multi-touch cancel tracking. Native opening reports to the parent so the narrow Project drawer closes.

The parent owns committed IndexedDB drafts and pending plain text. Native DSH owns input, optimistic bubbles, Session selection, admission/dispatch, and history. Admission acknowledges only after the parent transaction commits; native input clears afterwards. Replays preserve captured Project, Session, request ID, and Queue/Steer mode. The bridge exposes specific commands, not arbitrary RPC. Selection verifies the exact identity with native `session.projections({sessionId})`: failed reads remain retryable, and only a successful null response means missing. The shell scopes replies to the active request/navigation/document and clears selection notices independently of unrelated notices.

[The app contract](../../../../docs/project-app.md#native-integration-and-bridge) defines the envelope, handshake exceptions, directions, payloads, identity validation, and timeouts. Recovery probes the child-origin index every five seconds while disconnected/connecting, exchanges a fresh same-origin token inside the current frame, and reconnects native transport. Selected frames retain displayed state while authoritative baselines return.

Install through the Web profile's native `file:` dependency. The pinned published DSH `0.2.0-rc.2` CLI also requires the matching [owner patch](../../../../patches/deepseek-harness-project-app.patch): retained display, stable caller IDs, concurrent admission, embedded draft/admission hooks, and native layout behavior. Package peer admission alone does not establish these capabilities. Installed package files are snapshots; source-only changes require forced installation and a fresh target Runtime.

[Runtime maintenance](../../../../docs/dsh-runtime-maintenance.md) documents patch receipts, complete older-to-current transitions, the guest pnpm store, image/daemon/CLI distinctions, generated selector assumptions, and release pins. Native settings persistence remains the upstream policy: stock rc.2's non-loopback forms do not durably load/save profile preferences, and this bridge has no supported API to change that mode. Control text storage preserves a pending prompt's mode; it does not persist native settings.

Run [the frozen installation check](../../../../tests/dsh-plugin-install.test.mjs) for packaging/dependency changes and the affected native browser checks in [the app verification guide](../../../../docs/project-app.md#verification). Report physical-device/remote-path acceptance separately. Never run deployment or probes against the Runtime hosting the agent session.
