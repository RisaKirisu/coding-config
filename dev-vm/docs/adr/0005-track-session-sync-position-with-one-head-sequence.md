# Track Session Sync position with one head sequence

Session Sync keeps one local file, `/run/devvm/sync-status.json` in the DevVM's runtime directory, and one remote marker, `.sync-head.json` at the Project's Sync Store directory; both are excluded from transfer. The local file carries a display status, `head_seq`, the last error, and an update instant. The remote marker carries `seq`, `writer_id`, and an update instant. `head_seq` is the only durable sync position: it records the Sync Store sequence this workstation last exchanged. A push first confirms the remote `seq` equals `head_seq`, writes the marker with `seq + 1`, and on success stores that value as `head_seq`; a mismatch means the Sync Store is ahead. Startup reconciliation reads the remote `seq` first and branches on it. When it equals `head_seq`, this workstation was the last writer: it pushes then pulls with `--update`, and the pull is a no-op for `storages/`. When it exceeds `head_seq` — including a fresh workstation with no `head_seq` at all — another workstation wrote last: session logs and attachment objects still push and pull as a union, but `storages/` is pulled remote-wins and never pushed, and the local registry it replaces holds only what this workstation produced while behind. Either way the pull sets `head_seq` to the remote `seq`. When the Sync Store is unreachable the script changes nothing and records Degraded Sync; when its push fails it records failed. It never prevents the DSH Runtime from launching. The focus-time check compares the remote `seq` with `head_seq` in the same way. `writer_id` identifies the workstation: the Control Daemon generates it once when Session Sync is set up and stores it in the workstation-wide sync configuration, and the plugin copies it into the remote marker with every advance so a race between two pushes to the same sequence can be attributed. A workstation that has never reconciled has no `head_seq`; it is treated as behind, so its pushes carry only session logs and attachment objects until the first startup reconciliation sets the position.

Dirty Local State is not tracked. The boolean `.sync-dirty` marker this replaces was the cause of silent loss: it had to be set before a transfer and cleared after, so a change saved mid-transfer had its mark erased by a transfer that never carried it. A pair of local and pushed counters would have made that unrepresentable, but it would also have duplicated a ledger the filesystem already keeps — every synced file carries a modification time, which is the signal rsync decides on. Under ADR 0001's rules a reconciliation always pushes then pulls with `--update`, and pushing unchanged files is a no-op, so the question the marker answered — whether to push first — always has the same answer, and the UI already conveys unpushed work through the failed and degraded statuses.

Two conditions bind the local file. It is written atomically, by temporary file and rename, so a torn write cannot misreport the sync position. And it has one writer at a time, assigned by lifecycle rather than by convention: the startup script writes it before `dsh web` starts and the plugin writes it while the DSH Runtime runs, which the stop-before-pull invariant of ADR 0004 already guarantees. The Control Daemon only reads it.
