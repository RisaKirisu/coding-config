# Derive Session Sync state from counters in one status file

Session Sync keeps one local file, `.sync-status.json` beside the Project's Portable DSH State, and one remote marker, `.sync-head.json` at the Project's Sync Store directory; both are excluded from transfer. The local file carries a display status, `local_seq`, `pushed_seq`, `remote_seq`, `writer_id`, the last error, and an update instant. Everything else is derived: Dirty Local State is `local_seq > pushed_seq`, and the Sync Store is ahead when the remote marker's sequence exceeds `pushed_seq` or its writer is not this workstation. `local_seq` increments on every trigger; `pushed_seq` takes the value captured when a transfer started and only on success. This replaces a boolean `.sync-dirty` marker, which was not merely redundant but the cause of silent loss: a boolean must be set before a transfer and cleared after, so a change saved mid-transfer had its mark erased by a transfer that never carried it. Counters make that state unrepresentable rather than merely unlikely, and they remain answerable with the Sync Store unreachable, which a remote comparison such as an rsync dry run would not be.

Two conditions bind the file. It is written atomically, by temporary file and rename, because Dirty Local State now lives inside it and a torn write would present unpushed work as synchronized. And it has one writer at a time, assigned by lifecycle rather than by convention: the plugin writes it while the DSH Runtime runs, the Control Daemon writes it only while that runtime is stopped, which the stop-before-pull invariant of ADR 0004 already guarantees. The daemon must update it after a successful reconciliation, otherwise the ahead-of-store warning reappears immediately after the restart that resolved it.
