# Pull Portable DSH State only while the DSH Runtime is stopped

Portable DSH State is pulled from the Sync Store only when no DSH Runtime is running for the Project, and refreshing a running instance means restarting it: the Control Daemon stops the DSH Runtime, reconciles (pushing Dirty Local State, then pulling), then starts it again. DSH cannot absorb a pull underneath itself. A `storages/` unit is read once when it is opened and is thereafter authoritative in memory with the file as its projection; there is no watcher, reload, invalidation, or RPC for those units, and every mutation rewrites the whole file from memory with no cross-process locking and last-completion-wins. Pulling a unit under a live DSH Runtime therefore shows the user stale state and then destroys the pulled content at the host's next mutation, which is worse than not pulling. Session logs are more forgiving — the session list is a directory scan per request and a cold cached log is re-read when its stored revision changes — but the attached session is served from memory and never re-read, so a session-only pull would leave the registry, ordering, and archive state inconsistent with it. Hot in-place pull, host-side file watching, and a DSH-internal reload were all rejected on that evidence; an in-process restart is not available either, because the loader's process-exit hook ships empty.

Because the pull is deferred, the plugin must warn instead: when the Sync Store is ahead, it shows a persistent banner directing the user to the Control Daemon page to restart the DSH Runtime, and it suspends pushing `storages/` units while continuing to push session logs and attachment objects. Suspension is required because a whole-document push of a stale workspace unit would delete the other workstation's session references from the Sync Store, while session and attachment pushes stay safe under the union rules of ADR 0001. Warning is best-effort by choice: nothing blocks further turns, since blocking the composer costs more than the divergence it would prevent under the Single Writer Rule. The daemon must refuse to reconcile while its DSH Runtime state is running, so stop-before-pull is an invariant of the launch path rather than an ordering coincidence.
